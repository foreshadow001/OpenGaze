# GazeCapture 朝向轴系修复记录（2026-08-27）

由 gaze 方向分布可视化（`../viz/gaze_distribution_insightface_224.png`）发现的
"pitch≈0 时 yaw 只有负值、yaw≈0 时 pitch 只有负值" 异常切入，本文件记录完整的
定位过程、结论与修复状态。**dot→CCS 转换（dot_transfer.md §4 四朝向表）全程未改、
验证无误**；问题全部出在 CCS 之后的相机轴系一步。

## 1. 核心事实（全部实测）

1. **存储帧一律是「界面视角」**（app 按当前朝向旋转后存储），四个朝向的帧中
   **人脸全部正立**——原算法（GEN6+IDX6+按实际尺寸查内参的 estimateHeadPose）
   逐朝向实测头部 roll：ori1 -2.9° / ori2 -1.3° / ori3 -1.7° / ori4 -3.3°
   （n≈3000/120/920/920，中位；"ori2 的脸是倒的/横屏帧是传感器原生"均不成立，
   preprocessor.py 旧 docstring 中"传感器原生直出"表述有误）
2. 内参 30 个 xml 全部**主点居中 + 零畸变** ⇒ 帧平面内任何旋转下同一 K 文件
   数值上仍精确成立
3. 帧实际尺寸与朝向号**不严格对应**：如 iPad Air 2 的 ori4 帧实为 480×640
   （竖屏形状），00028 的 5 个 ori3 帧也是 480×640——**内参必须按实际帧尺寸查**，
   按"朝向→尺寸"直觉硬编码会用错 K（PnP 角度出 ~180° 垃圾）
4. 逐朝向标签分布（修复前）：ori1 物理正确（俯视+yaw 居中）；ori2 pitch 应仰
   实为俯；ori3/4 的 yaw 双双落在同一侧（应两侧）

## 2. 轴系模型（修复的推导基础）

界面视角轴系相对 ori1 界面轴的旋转：ori1 = 0°、ori2 = 180°、ori3 = -90°、
ori4 = +90°（即 ori2/ori4 各与自己的"正参照"差 180°）。CCS→处理帧相机系的
映射 = ori1 映射 M1=(-ccs_x, +ccs_y) 按上述角度做平面旋转：

| 朝向 | 旋转 | 正确映射 | 修复前代码 | 后果 |
|---|---|---|---|---|
| 1 | 0° | (-ccs_x, +ccs_y) | 同 | ✓ 正确 |
| 2 | 180° | (+ccs_x, -ccs_y) | 用了 ori1 的式子 | pitch/yaw 双取反 |
| 3 | -90° | (+ccs_y, +ccs_x) | 同（LANDSCAPE_SIGN=+1） | ✓ 正确 |
| 4 | +90° | (-ccs_y, -ccs_x) | 与 ori3 共用同一符号 | pitch/yaw 双取反 |

受影响帧：ori2 ≈4% + ori4 ≈32% ≈ **36% 的 GC 训练标签符号错误**。

## 3. 已落地的修复

1. **`_gaze_point_cam`（preprocessor.py）**：ori2/ori4 在原映射基础上取反 (x,y)
   ——与轴系模型严格一致；等价于给四朝向各配正确"旋转后的内参"（主点居中下
   数值相同）。已验证：修复后分布 ori2 pitch +14°（仰视✓）、ori4 yaw +11°
   （另一侧✓）、四朝向构成物理自洽的"十字形"（俯/仰/左/右）
2. **第一版全量重预处理**（进行中，~3.8h，覆盖写 ylx/gazecapture_insightface_224）：
   patch 与旧产物逐字节一致（roll 在归一化中自洽），仅 gaze 标签被修正；
   "原地取反"修 h5 为近似解（眼睛 z≈500mm 平移项，差 ≤5.5°），弃用
3. **建模端口内参查找**：改为按每朝向实际帧尺寸（读 1 帧）查 xml，弃用
   ORI_SIZE 硬编码表（00002 验证三朝向 33~38° 全通过）
4. 撤销过一次错误尝试：曾按"ori2/4 帧内人脸倒置"假设翻转特征点——roll 实测
   证伪后已回退（该尝试曾把 00028 的 ori4 从 33° 弄到 174°）

## 4. 排除的疑点（记录以免回头重查）

- 00028 的 "ori3 中位角 180°"：该 session ori3 仅 5 帧（朝向切换过渡帧），
  120 帧采样抽到 1-3 帧噪声所致，非系统 bug（逐帧实测该 5 帧 PnP 角中位 35°）
- "ori2/ori4 帧内人脸 roll≈180°"：不成立（见 §1.1）
- 内参主点偏移：0（全部居中），非残差来源

## 6. yaw 全量取反修复（2026-08-28）

**发现方式**：用户观察归一化样例图（normalized_samples_insightface_224.png）中 GC 的
瞳孔偏转方向与 (θ,φ) 标注不一致。

**诊断实验**（viz/yaw_diagnostic.png）：取各数据集 yaw 极端样本（最负 3 + 最正 3），
在图像上画标签方向箭头（绿）叠加瞳孔位置——MPII 和 EVE 的箭头与瞳孔一致，
**GazeCapture 完全反向**（φ<0 样本瞳孔向右偏转）。

**根因**：iOS 前摄保存帧未镜像（AVCaptureVideoDataOutput 默认），人物右侧在图像左侧
（相机 -x）。原 CCS→相机系映射中 x 分量的符号与此相反，导致全部帧 yaw 取反。
pitch 不受影响（y 分量正确）。

**修复**：`_gaze_point_cam` 返回值 x 取反（一行改动，四朝向统一生效）。
验证：修复后单 session yaw 相关 -0.992（全量翻转）、pitch 相关 0.995（不变）。

**波及**：GC 全量标签需重预处理 + 重训 + 重测（第三轮）。
